# Severity assessment

The engine extends the existing complaint workflow. Submission and report evidence writes queue a row in `severity_assessments` transactionally. The client requests `POST /api/severity` after submission/uploads; the authenticated route checks complaint access using RLS, atomically claims the job, returns 202 and runs it with Next.js `after`. Saving a complaint never depends on the assessment provider succeeding. Citizen and assigned-officer dashboards share the result panel and list priorities. Existing routing, status transitions, private evidence and appeals are unchanged.

## Scoring and uncertainty

Each factor has a validated score of 0–100 (or null for unknown), explanation and confidence of 0–1. Backend code multiplies scores by their weights; model totals are never accepted.

| Factor                  | Weight | Source and rubric                                                                                                                                                                                                                                             |
| ----------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hazard type             | 30     | OpenRouter evaluates category and locally extracted, allowlisted hazard signals. Scale: minimal 0, minor 25, moderate 50, serious 75, immediate threat 100. Reported, not independently verified.                                                             |
| Visual severity         | 25     | One consented report image, same scale. Unknown without explicit consent, a configured vision model, usable image, or relevant/clear evidence.                                                                                                                |
| Nearby sensitive places | 15     | OSM/Overpass school, kindergarten or hospital within 350 m of rounded coordinates: hospital 100, school/kindergarten 80, no mapped matches 0. Map incompleteness remains explicit; lookup failure is unknown.                                                 |
| Road importance         | 10     | Highest mapped road within 100 m: motorway 100, trunk 90, primary 80, secondary 60, tertiary 40, residential/unclassified 20, service 10. Nominatim highway tags are a fallback. Adjacent roads may be returned; ownership remains unverified.                |
| Weather                 | 10     | Fresh Open-Meteo current precipitation and wind. Rain ≥10 mm →100, ≥2→60, >0→30, else 0; wind ≥60 km/h →100, ≥40→60, ≥20→30, else 0. Use the larger value. Missing/stale/invalid weather is unknown.                                                          |
| Citizen corroboration   | 10     | 25 points per distinct other citizen (maximum 100) with the same category within approximately 200 m and 30 days. Requires consented coordinates. Accounts/reports are not independently verified; no other citizen identities or descriptions are disclosed. |

Bands are P1 (70–100), P2 (45–below 70), P3 (20–below 45), P4 (0–below 20). The stored score retains two decimal places. With unknown factors, the final score and weighted priority are null; show the minimum–maximum possible score and known-factor weight instead. Unknown is never interpreted as zero risk. Aggregate confidence is weighted over all six factors (unknown contributes zero), and is an advisory confidence indicator, not a calibrated probability. Factor reasoning identifies uncertainty.

A separate emergency override flags P1 for citizen-declared immediate danger or existing English/Tamil danger signals (live wires, fire, injury). It does not inflate the weighted score, verify the emergency or dispatch assistance. Both dashboards advise contacting emergency services directly. Automated signals can miss threats; human review remains necessary. There are no response-day promises or expiry-driven closures. Historical `due_at` is retained for compatibility; new submissions leave it null.

## Privacy and provider boundaries

Severity sends only category and locally extracted hazard signals to OpenRouter, not raw complaint text, location, names, citizen IDs or corroborating reports. This is separate from the existing intake endpoint, whose existing description-based behavior remains unchanged. Model output is untrusted and schema-validated. No provider response, image, complaint, token or address is logged.

Image consent is optional, separate from report submission consent, unchecked by default, and saved with the report. Without consent, the worker does not read image objects for AI. With consent and a configured vision model, it downloads one registered report image from private storage, validates its signature, decodes it with a pixel limit, resizes it to at most 1024 px and re-encodes JPEG without EXIF/GPS metadata. Original evidence is unchanged. This is not face/plate redaction: citizens must remove visible personal information before opting in. Resolution proof, audio and video are never sent. OpenRouter requests require no-training/data-collection-denied provider routing; unsupported routing/model combinations fail safely.

Location context has its own optional consent and incident-coordinate fields. Coordinates are rounded to three decimals before external transmission. No address geocoding or automatic browser geolocation occurs. OSM provides mapped context, not authoritative asset ownership or exhaustive nearby-place coverage. A successful empty map response does not prove there are no sensitive places. Open-Meteo is regional current weather, not on-site measurement. Corroboration is calculated privately in SQL from consented coordinates; it is not an AI guess.

## Activation

1. Keep the existing Supabase setup, then apply `supabase/migrations/202611010002_severity.sql` after `202611010001_civiclens.sql`. It adds assessment storage, RLS read access matching existing complaint visibility, restricted service-role functions, queue/invalidation triggers and a private Nominatim rate gate. It replaces only submission's date-target assignment, preserving validation, routing and events. It does not enqueue historical reports automatically or modify existing complaint/evidence/event policies. An authorized dashboard retry can explicitly assess a historical report, with no inferred image/location consent.
2. Set the existing `NEXT_PUBLIC_DEMO_MODE=false`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, server-only `SUPABASE_SERVICE_ROLE_KEY`, `OPENROUTER_API_KEY` and `OPENROUTER_MODEL`. No new mandatory API key is introduced. Browser-only demo does not call this backend or manufacture severity results.
3. Optionally set server-only `OPENROUTER_VISION_MODEL` to an available vision-capable model accepting JSON and the privacy routing parameters. Without it visual assessment is unknown. Optionally set `NOMINATIM_USER_AGENT` to your genuine identifying application URL/contact. Nominatim calls use a database-backed global maximum of one request per second and Next's 24-hour response cache; denied slots skip the lookup. Check the public Nominatim usage policy and use a supported dedicated service for production traffic. Do not invent a contact identity.
4. Allow outbound HTTPS to `openrouter.ai`, your Supabase project hostname, `nominatim.openstreetmap.org` (if enabled), `overpass-api.de` and `api.open-meteo.com`. OSM/Overpass and Open-Meteo do not require keys for this implementation. Follow provider usage/licensing and attribution requirements: [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/), [Open-Meteo terms](https://open-meteo.com/en/terms). Confirm eligibility for your deployment's traffic/commercial usage; use suitable provider hosting/plans where required.
5. Configure a trusted scheduler to invoke `GET /api/severity` with `Authorization: Bearer <CRON_SECRET>` (server-only secret). The endpoint refuses requests without the secret and refuses demo mode. For Vercel, add a cron entry for this path in deployment configuration and set `CRON_SECRET`; choose a frequency supported by your plan. No scheduler is automatically provisioned by this commit. One oldest eligible job is processed per invocation; choose capacity/frequency for workload. Without a scheduler, the submitting client and dashboard retry still work, but browser-disconnected jobs wait for another request. Function duration must allow 60 seconds.

Jobs use atomic claims, unique leases, a two-minute crash-recovery timeout, a 30-second retry cooldown and at most three claims per input version. Claims share the existing 30-request-per-citizen daily AI quota. Each claim makes at most one model request. Context requests time out at eight seconds and the model at twenty seconds. Failed jobs retain safe error/status information and any partial factors. A scheduler or authorized retry recovers pending/failed/expired jobs; partial results can be retried from the dashboard within the same cap. New report evidence invalidates the previous lease/result and queues a fresh assessment; resolution evidence does not. Old workers cannot overwrite a newer input version. After exhausted retries, manual review is required. This is an at-least-once queue, not a guarantee of provider availability or immediate completion.

## Validation and hosted checks

`npm test` exercises weights/bands, unknowns, confidence, invalid provider responses, consent, privacy, external failures, authenticated async routes, queue leases, SQL quota/RLS and corroboration using PGlite. Run `npm run typecheck`, `npm run build` and existing desktop/mobile Playwright journeys as well. Tests mock external providers and never incur paid AI usage.

For hosted activation, apply the migration and configure providers/scheduler, then sign in and submit a real non-sensitive report. Confirm 202 followed by persisted status/results on both authorized dashboards. Compare consent-off with a consented image and verify unknown visual scores when unavailable. Confirm unrelated citizens and departments cannot read or request assessment. Disconnect external APIs to verify failure/partial state, retry recovery and preservation of the original report. Submit immediate-danger wording to check the separate override. Stop the browser before kickoff and verify scheduled recovery. Add new report evidence while a worker is running and verify that only the fresh lease can finish. These live checks require your deployment credentials; mocked tests do not establish hosted readiness.
